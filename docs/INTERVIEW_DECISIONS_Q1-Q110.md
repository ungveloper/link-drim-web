# 인터뷰 Q1–Q110 결정사항 색인

> 2026-10-29 기준 8차 인터뷰에서 확정된 답변을 *질문별로 요약*한 문서입니다. 사용자 발언의 축어록이 아니며, 전체 맥락과 기술적 세부사항은 `PRD_v0.9.md` 참조. 미확정 정책은 추천안/검증 필요로 표시.

## 1차 — 서비스 목적과 고객 (Q1–Q8)

- **Q1:** 5개 경쟁 서비스의 장점을 모은 국내 친화적 플랫폼. 특정한 단일 불만보다 핵심 경험의 통합이 목적.
- **Q2:** 첫 고객은 1인 기업 대표, 개인 브랜딩에 관심 있는 전문직 및 병원 원장. 추후 확장.
- **Q3:** 비전문가도 쉽게 다루는 정돈된 프로필·링크 중심. 과도한 자유형 랜딩 빌더 지양.
- **Q4:** 고객별 전환 목표가 다름. 여러 UI 템플릿에 동일한 고객 데이터를 재사용.
- **Q5:** 고객 셀프 관리와 운영자 대행 제작 모두 지원, 제작 후 권한 이관, 여러 고객 관리.
- **Q6:** 관리의 쉬움, 깔끔한 노출, 상세한 유입·행동 통계가 최우선.
- **Q7:** 초기에는 직접 발급·납품한 고객 계정만 사용. 수익화·일반 가입은 향후 검토.
- **Q8:** 혼자 운영, 초기 비용 최소화. 목표는 실제 납품 가능한 완성도.

## 2차 — 템플릿 기반 편집 (Q9–Q20)

- **Q9:** 고객 유형별 필수 필드 목록은 운영하며 확장. 하나의 공유 데이터에 여러 UI 템플릿 바인딩.
- **Q10:** `/profile`, `/business-card`, `/link` 등 템플릿 경로 기반 공개 페이지; 선택한 페이지 활성화 및 공유 데이터 재사용.
- **Q11:** 완성형 템플릿 미리보기·선택, 필요한 입력 폼 자동 생성, 필수값 검증.
- **Q12:** 고객은 하나의 관리 화면에서 상단 템플릿 선택→필수 데이터 입력→저장.
- **Q13:** PC·모바일 편집 기능 동일, 반응형 UI.
- **Q14:** 명시적 저장 즉시 공개 반영, 저장마다 이력 기록, 최고 관리자 복구.
- **Q15:** 업종별 템플릿을 확장하되 공통 템플릿 메커니즘 사용. 제한적 디자인 조정.
- **Q16:** 고객은 색상·배경·대표 이미지 등 간단한 옵션만 변경.
- **Q17:** 일별 방문·링크별 성과·SNS 유입·다음 행동·버튼 CTR·방문 시간대·체류 시간.
- **Q18:** 초기에는 외부 예약·카카오 상담 URL 이동 이벤트까지 측정.
- **Q19:** 관리자 사이트 생성·초기 제작→고객 확인→초대 링크를 통한 Google/Naver/Kakao 로그인 연결.
- **Q20:** 고객이 구매한 개인 도메인 연결 지원.

## 3차 — 멀티사이트·권한·데이터 (Q21–Q35)

- **Q21:** 한 소셜 계정으로 여러 사이트 관리. 잘못 연결된 계정은 최고 관리자가 권한 해제·재초대.
- **Q22:** 각 URL은 활성 디자인 1개. 맞춤 템플릿은 특정 고객에게만 제공, 최고 관리자는 전체 조회.
- **Q23:** 초기에는 공통 데이터 동일 표시, 등록 항목 순서 정도만 고객이 조정.
- **Q24:** 새 공용 템플릿은 기존 고객에게 NEW로 노출, 기본 미선택.
- **Q25:** 링크 개수 무제한, 고정·정렬, 카드/리스트 UI. 예약 공개는 이후 Q43에서 후속 버전으로 최종 보류.
- **Q26:** 더미 디자인 미리보기와 실제 고객 데이터 미리보기 모두 지원.
- **Q27:** 사이트 공통 Primary·Secondary·Background 3색, 기본 블랙/화이트.
- **Q28:** 고객 관리자 한 URL에서 접기/펼치기 중심의 쉬운 정보 편집.
- **Q29:** 누락 데이터/잘못된 페이지 상태는 운영 오류로 기록하고 최고 관리자 확인.
- **Q30:** 일회용 초대 URL을 통한 소셜 로그인 연결, 추후 재연동 지원.
- **Q31:** 한 사이트에 여러 관리 사용자 연결 허용.
- **Q32:** 고객이 직접 도메인 연결 가능, 쉬운 안내 제공.
- **Q33:** 활성 템플릿 중 대표 페이지 하나 선택, 도메인 루트에 표시.
- **Q34:** 최근 30일·90일·1년 통계 조회, 장기 보관·확장 고려.
- **Q35:** 개인 개발·테스트 시 Vercel Hobby 우선, 상업적 납품 시 Pro 전환 계획.

## 4차 — 오류·관리·측정 (Q36–Q50)

- **Q36:** 필수값 누락 시 저장 차단·해당 필드 포커스·운영 오류 기록·Notion 오류 DB에 반영. 최초 비공개는 준비 중.
- **Q37:** 로그인·도메인·이미지·렌더링·통계 등 전 오류의 발생/상태/해결 관리.
- **Q38:** 초기 고객은 동일한 사이트 콘텐츠 편집 권한. 복잡한 고객 내부 역할 계층 불필요.
- **Q39:** 최고 관리자만 사이트별 특정 계정 권한 해제, 전체 초기화, 건별 초대 링크 발급.
- **Q40:** 고객은 멤버 초대·제거 불가, 최고 관리자에게 요청.
- **Q41:** 맞춤 템플릿도 공통 데이터 재사용, 추가 필드만 확장.
- **Q42:** 링크 정렬은 드래그와 위/아래 버튼 모두 제공.
- **Q43:** 초기 링크는 공개/비공개만, 예약 노출은 향후 확장.
- **Q44:** 페이지 조회·세션·추정 고유 방문자 분리 및 가능한 범위의 봇 제외.
- **Q45:** SNS별 UTM 추적 링크 복사 제공.
- **Q46:** 익명 페이지 이동·버튼 클릭 흐름을 통계로 제공.
- **Q47:** 추정 평균 체류 시간과 인기 링크 TOP 5 표시.
- **Q48:** 고객 메뉴 2개만: `성과 분석`, `페이지 관리`. 성과 화면은 핵심 KPI 우선, 과도한 설명 지양.
- **Q49:** 고객의 셀프 도메인 연결과 단계별 DNS·검증 안내.
- **Q50:** 모든 저장·초기화·복원은 이력으로 남김. 최고 관리자만 diff·롤백·초기화. 통계·권한은 복원 범위 제외.

## 6차 — URL·저장·장애·배포 (Q66–Q80)

- **Q66:** 서비스명과 기본 도메인은 인터뷰 종료 후 코드 확인 전에 결정.
- **Q67:** 고객이 사이트 URL 식별자 변경 가능. 사전/최종 UNIQUE 검사, 이전 주소 리디렉션·예약 없음.
- **Q68:** 검색 노출 ON/OFF, 필요시 상세 SEO 입력 제공.
- **Q69:** 공통 데이터로 OG 제목·설명·이미지 자동 생성, 대표 이미지 수정 가능.
- **Q70:** 저장 직전 DB revision 비교, 타 사용자 변경 있으면 저장 거부·안내.
- **Q71:** 전체 초기화에는 확인창과 고객 사이트명 직접 입력 필요.
- **Q72:** 최고 관리자에게 GitHub식 변경 전후 diff, 과거 버전 목록·복구.
- **Q73:** 이미지 형식·크기 검증 및 클라이언트 편집·압축 후 최적화 저장.
- **Q74:** 모바일 우선·320px 대응·터치 사용성·메타데이터 등 제안 품질 기준 적용.
- **Q75:** 렌더 오류 시 마지막 정상 공개 상태 우선, 불가하면 안내·Notion 오류 기록.
- **Q76:** 미리보기는 통계 제외, 관리자의 일반 공개 URL 접속은 별도 구분.
- **Q77:** 통계 실패는 페이지 이용을 방해하지 않고 운영 오류·누락 기간 표기.
- **Q78:** 사이트 생성 폼 최소 필드: 고객 사이트 이름·slug·최초 템플릿·공개 상태.
- **Q79:** 새 공용 템플릿은 테스트 후 배포, 긴급 중단 가능.
- **Q80:** 최초 납품 전에 인증·권한·폼·템플릿·반응형·통계·도메인·Notion·복구·격리 테스트 필수.

## 7차 — 기술·데이터·템플릿 엔진 (Q81–Q95)

- **Q81:** Next.js App Router/TypeScript, Tailwind, shadcn/ui, Supabase, Vercel, Zod, Vitest/Playwright, Notion.
- **Q82:** 고객 `/dashboard`와 최고 관리자 `/admin` 라우트 분리.
- **Q83:** 템플릿은 코드 컴포넌트와 필드 스키마로 추가, 사용자 입력 폼 자동 생성.
- **Q84:** 템플릿 코드/스키마 버전 고정, Sonner 알림·미리보기 후 고객이 명시적으로 업데이트.
- **Q85:** 고객 전용 템플릿도 동일 Next.js 프로젝트에서 개발·권한 분리.
- **Q86:** 신규 템플릿 필드는 기존 사용자에 영향 최소화, 업그레이드 시 검증.
- **Q87:** 공통 주요 필드는 관계형 DB, 맞춤 확장 필드는 JSONB 병용.
- **Q88:** 미저장 변경 이탈 경고와 임시 입력 보존, 자동 공개는 하지 않음.
- **Q89:** 모든 이력·이미지 복구 가능성을 최대한 유지, 추후 외부 스토리지 아카이브.
- **Q90:** 기본/개인 도메인 대표 주소 선택, 개인 도메인 연결 시 canonical 우선.
- **Q91:** 자체 이벤트 분석 우선, GA4·Meta 픽셀 등은 추후.
- **Q92:** 운영 DB 원본은 일정 기간, 오래된 원본 아카이브, 일·월 집계 장기 유지.
- **Q93:** 사이트 단위 RLS 및 서버 권한 검증 필수.
- **Q94:** 로컬/미리보기/운영 환경 분리와 테스트 통과 후 배포.
- **Q95:** 초기 예상 고객 사이트 5~10개.

## 8차 — 최종 정책 확정 (Q96–Q110)

- **Q96:** 대표 템플릿 해제 시 다른 활성 템플릿 지정 필요, 모두 해제하면 준비 중.
- **Q97:** 비활성 템플릿은 HTTP 404와 짧은 안내 제공.
- **Q98:** 고객은 디자인 버전 업그레이드만 가능, 직접 다운그레이드 불가와 주의 안내.
- **Q99:** 템플릿 경로 `/profile`, `/business-card`, `/link` 등은 고정. 고객이 바꾸는 것은 앞단의 사용자 slug뿐; 개인 도메인 루트는 대표 템플릿.
- **Q100:** 사용자 slug 플랫폼 전체 UNIQUE, 시스템 예약어 차단.
- **Q101:** 개인 도메인 소유권·연결 상태 주기 검증, 일시적 장애로 원본 사이트 삭제 금지.
- **Q102:** SEO 상세 설정은 초기에는 사이트 전체 1개 세트.
- **Q103:** 명함 vCard 저장 및 QR코드 공유 포함.
- **Q104:** URL·전화·이메일·예약·카카오 상담 클릭을 별도 이벤트로 측정(완료 여부와 구분).
- **Q105:** 최초 연결 후 페이지 관리 우선, 일반 로그인은 성과 분석 우선; 사용자별 첫 화면 변경 허용.
- **Q106:** 초기 super_admin 1명, 미래 추가 가능한 별도 platform_admin Role 설계.
- **Q107:** 오류 상태 양방향 동기화 충돌은 기록·재검증 후 반영.
- **Q108:** 원본 이벤트 운영 DB 90일 기준, 오래된 기록 아카이브.
- **Q109:** active/suspended/pending_deletion 상태, 최고 관리자만 중지·삭제·복구.
- **Q110:** 데이터 내보내기 초기 제공(고객 자기 데이터, 최고 관리자 범위별 내보내기).
